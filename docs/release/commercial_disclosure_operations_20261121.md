## 決定と今回の範囲

氏名・住所・電話番号は、消費者からの請求に応じて開示する方式を採用する。公開案には、請求窓口と、申込みの意思決定に先立って十分な時間的余裕をもって確認できるよう、書面又は電子メール等で遅滞なく提供する旨を記載する。

公開窓口は既存の `gotainu@gmail.com` を、問い合わせ・特商法開示請求・契約課金・不具合で共用する。自宅住所・個人電話を常時公開する方針や、バーチャルオフィスの契約は採用しない。バーチャルオフィスは必要になった際の将来検討にとどめる。メール差出人の表示は現在の HamCare／Go / hamster well-being 等のブランド表示を維持し、個人本名へ変更しない。請求に対して開示する法定の事業者情報と、メール差出人のブランド表示を混同しない。

この文書は公開前に整備した運用手順に11/28の本人確認・採用方針を反映したものである。本人申告と実際の開示メールの配送検証は区別し、この文書だけで購入受付や一般公開を開始しない。事業者の氏名・住所・電話の実値は、本書、監査台帳、チャット、テストデータへ転記しない。個人値をリポジトリへ追加しない。

当初の公開案整備は特商法ページ・サポートページと本書を対象とした。11/28は本書の本人確認・方針反映だけとし、公開HTML、氏名・住所・電話の公開切替、メールの実送信、本番配備、Stripe・既存契約・課金機能は変更しない。料金表示は確定済みの「月額550円」とする。

## 公開案の内容

- 特商法ページに、氏名・住所・電話を請求開示する旨、購入前から請求できる旨、提供方法と提供時期、既存のメール窓口を明示する。
- 件名を入力済みのメールリンクを設け、請求方法を分かりやすくする。特定の件名でない請求も受け付ける。
- サポートページにも事業者情報の開示窓口を設け、通常の不具合対応を順次返信する案内と区別する。
- 登録、ログイン、有料契約、購入の確約を開示の条件にしない。開示が必要な人に、情報受領前の申込みを求めない。

## 請求を受けた際の手順

1. 既存のサポート窓口で「事業者情報の開示請求」と分かる連絡を受け付ける。表題の完全一致や購入済みであることを条件にしない。
2. 個人事業者の氏名は戸籍上の氏名又は商業登記された商号、住所は現に活動している正確な住所、電話は確実に連絡を取れる番号を、運営者が管理する非公開の正本で確認する。法人である場合の名称・責任者等の要件は、実際の事業者形態に合わせて確認する。屋号やサイト名だけ、番地の欠落、私書箱だけ、連絡不能な電話で代替しない。
3. 確認した広告表示事項を、請求者が保存・確認できる書面又は電子メール等で遅滞なく提供する。受領確認や本ページへのリンクだけをもって開示完了にしない。購入判断の前に十分な時間的余裕をもって確認できる状態にする。
4. 不達・誤送信・問い合わせの行き違いを確認し、未達のまま完了にしない。相手が取引を確約しないことを理由に開示を拒まない。
5. 受信日時、対応日時、送信成否と対応完了の事実は必要な範囲で非公開に記録する。事業者の個人値、請求者のメール本文・個人情報を開発用の記録やGitへ複製しない。

### 原本の確認と提供文案

Goは、正確な事業者氏名、番地等を欠かさない実際の活動住所、確実に連絡を取れる電話、内容の確認日を本人管理の安全な私有保管先で確認する。PCを使えない時も本人が参照できる状態を保つ。原本の所在・実値はこの文書や公開ページへ追加しない。更新があれば次の開示前に正本を照合し直す。

開示時は既存ブランド名で返信し、例えば「HamCare運営です。事業者情報を次のとおり開示します。事業者の氏名：［原本から記入］、住所：［原本から記入］、電話番号：［原本から記入］、お問い合わせ：既存サポート窓口。」の必要項目を私有の返信文案に記入する。ブランド名を法定の氏名の代替にせず、最新の公開販売条件との矛盾も確認する。誤宛先・不達・行き違いを照合し、リンクだけの返信や送信受付だけで実到達確認済みと記録しない。今回、この文案で実メールを送っていない。

### 一般問い合わせ・開示履歴の手動整理（11/28採用、実整理未実施）

対象は、解決又は実際の開示完了を確認した一般問い合わせ/開示請求のメール本文・添付・作業コピー・対応メモ。返答しただけ、URLを送っただけ、不達、未解決、返金待ち、再申立てがある案件は完了にしない。事業者情報の非公開正本そのもの、Auth/利用者本体/課金データはこの整理対象ではない。

1. Goが**週最初の営業日**に、日本時間で完了日から90日を経過した受付を既存対応記録から確認する。自動TTLや新しい管理表は設けない。
2. 法令上の保持、課金・会計、紛争・異議、未完了・調査中、別の未解決受付に必要な資料のいずれかに該当するかを判定する。該当する場合は整理を保留し、必要な目的・理由と次回確認日を残す。法定記録の年数をここで推測しない。
3. 対象になる本文・添付・作業コピーの不要な個人情報を削除又は目的に必要な最小限へ整理する。複数の案件が混在するスレッドは全体を一括削除せず、対象部分だけを整理又は理由付き保留にする。Gmailのゴミ箱移動だけで完全消去済みと記録しない。
4. 既存の対応記録へ受付番号・分類・完了日・整理日・結果又は保留理由/次回確認日を残す。氏名・メール・UID・確認proof/token・本文を整理記録へ複製しない。受付番号等の最小記録も匿名化を保証するものとはしない。
5. 削除申請の窓口履歴は、確定済みの完了90日/未確認失効30日を[既存削除運用](web_account_deletion_support_20261121.md)の別条件で扱う。削除フェンス、再試行、課金停止証跡、会計記録、Webhook receipt、通知outboxへ一般窓口の90日を一括適用しない。

この方針の採用時点では、履歴の抽出・削除・最小化を実行していない。実際に整理した範囲と保留を、その実施後に記録する。
