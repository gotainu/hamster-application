## 3. 長期ビジョン（将来構想）

適切な同意を得た利用者の飼育データを、種類・年齢・性別・飼育環境・個体別行動履歴・温湿度・観察記録と対応付けて集約し、次を段階的に実現する。

1. 同種・類似環境の集団との比較。
2. 飼育環境や属性を考慮した個体差の推定。
3. その子自身の予測値からの日次乖離の検出。
4. 十分なデータ、診断ラベル品質、外部検証を満たした場合の疾患関連リスク予測研究。

初期の予測対象は**回し車の走行距離・回転数**とする。研究集団との比較、個体内の記述統計、個体の予測値を区別し、予測結果を病気や健康状態の診断として表示しない。

## 5. モデル比較方針（将来のオフライン検証）

| 目的 | 比較対象 |
|---|---|
| 基準モデル | 既存の個体別中央値、EWMA。既存の計算・観測選択を作り直さない。 |
| 数値予測（走行距離等） | Ridge回帰、ベイズ回帰、Gaussian Process Regression（GPR）。 |
| 回転数の予測 | Poisson回帰、負の二項回帰。計測方法・観測時間・分布の適合性を確認する。 |
| カテゴリ予測 | 二項ロジット、多項ロジット、順序ロジット、順序プロビット。カテゴリの意味・順序とラベル品質を先に確定する。 |
| ユーザー横断の個体差 | 混合効果モデル、階層ベイズモデルを将来比較する。 |

モデルの高度さではなく、同じ評価データでの基準モデルに対する予測性能の改善、不確実性の妥当性、説明可能性、運用時の再現性で採用を判断する。改善が確認できなければ基準モデルを維持する。現段階で特定モデルの採用や性能を約束しない。

## 6. 個体差と日次残差を分離する

- **持続的な個体固有の特徴**: 環境・属性を調整した後にも複数の観測期間にわたって残る個体差。十分な繰り返し観測と不確実性の評価が必要となる。
- **日次残差**: その子自身の予測値と特定日の実測値との差。観測日、予測時点、対象値、予測値、区間/確率、残差を対応付ける。

単一日の大きな残差を恒常的な個性として扱わない。日次乖離だけから疾病、環境の因果効果、性格を断定しない。環境調整後の差も、未測定要因がないことを保証するものではない。

## 7. 将来のデータモデリング要件

既存メダリオン構造を維持し、予測用の追加契約は後続の個別設計で確定する。候補フィールドや保存先をこの資料だけで実装しない。

- **飼育環境の変更履歴を優先課題とする。** 現在値しか保持しない`main_env`を過去全期間の環境として利用しない。変更の有効日時、記録日時、由来を保持し、観測時点の環境を復元できる設計を検討する。過去に未保存の履歴を推測で作らない。
- エンリッチメントの追加・削除、種類・数量の履歴を観測日に対応付ける。
- 計測方式、直径/換算仕様、センサー稼働状況・観測時間・計測品質を保持する。
- 欠測、未回答、不正値、センサー停止、**実測ゼロ**を区別する。欠測を0へ補完しない。
- 観測時点の年齢・性別・繁殖状態と、不明/未確認の状態を保持する。
- 観測日時、予測時点、対象日、入力cutoffを分離し、その時点で利用できた入力だけを使う。
- 獣医師確認済みの診断情報を扱う場合は、診断時点、確認主体、ラベルの由来・品質・同意の範囲を別途設計する。自由記述や心配タグを診断ラベルとして扱わない。
- 観測Evidence fingerprint、発見のsemantic signature、予測モデルversion/入力契約versionは責務を分ける。入力が変化した事実と、新しい発見、予測の変更を同一視しない。
- 現在の分析結果と、レポート生成時点の不変snapshotを引き続き区別する。モデル更新で過去レポートを書き換えない。

## 8. Prediction Ready（将来の別判定）

7記録日・14暦日のbaseline readyを予測モデルの利用可否へ流用しない。数値的な閾値をこの資料で一律確定せず、対象・モデル・計測方式に応じた検証で決める。

| 判定軸 | 確認すること |
|---|---|
| 対応付けられた観測数 | 目的変数と予測時点の特徴量が正しく対応する有効標本数。単なるdocument数ではない。 |
| 観測期間 | 時間を分けた検証や対象の変動を評価できる期間があるか。 |
| 欠測率 | 目的変数・各特徴量の欠測を区別し、補完で性能を誇張しないか。 |
| 特徴量の変動 | 個体内/個体間の変動が推定可能か。一定の入力だけで効果を断定しない。 |
| 測定方式・品質 | 方式の違い、変更、稼働時間、単位、品質が把握できるか。 |
| 時系列での予測性能 | 時間順検証で基準モデルに対する改善が確認できるか。 |
| 予測区間・確率の校正 | 予測区間のcoverageや確率のcalibrationが妥当か。 |

不足時は予測値やリスクを発行せず、既存の記述的Insight/基準値へ安全に戻す。準備完了は疾患予測や医学的妥当性の保証ではない。

## 9. 評価・プライバシー・研究上の条件

### 評価

- 時間順の学習・検証を行う。将来の測定、後日の診断・訂正、将来を含むbaselineを過去の予測入力に混ぜない。
- ユーザー横断モデルでは個体単位の分割と時間順の分割を設計し、同一個体が学習・評価へ不適切に混在しないようにする。既知個体の将来予測と、未知個体への汎化性能は別々に報告する。
- 全モデルを同じ評価条件で比較し、予測性能、予測区間のcoverage、予測確率のcalibrationを評価する。種別・計測方式などの差を平均値だけで隠さない。
- 採用時は入力cutoff、モデル/version、評価対象、評価期間、不確実性、利用制約を記録し、再現可能にする。

### 同意とデータ保護

ユーザー横断の集計・学習には、用途を明示した適切な同意、アクセス制御、必要最小限のデータ利用、プライバシー保護を必須とする。日常の記録保存への同意を、横断学習や疾患研究への同意とみなさない。匿名化等の方法、保存期間、利用停止・撤回への対応は研究/運用の個別設計で定める。

個体名、memo、質問/回答本文等を予測のために無条件で集約しない。研究用データは個別の読取・利用権限を設計し、本人用Firestoreの広範な読取許可を追加して代用しない。

### 疾患関連リスク

疾患関連リスク予測は、十分なデータ、獣医師確認済み診断ラベルの品質、時間的整合性、外部検証を満たすまで**研究目標**として扱う。未検証のリスク表示や診断をアプリへ追加しない。研究の成功を、医療用途の適合性や診断性能の保証として扱わない。

以下の既存長期順序は過去の合意として保存する。今回の近接優先順位を優先するが、研究仕様C-01/P-12のT-A/T-O比較計画や疾病研究を自動実装・削除しない。

## 10. 正式な開発順序

次の順序を採用する。後続段階は前段の品質・データ利用条件を確認してから進める。

| 順序 | 段階 | 完了判断の方向 |
|---|---|---|
| 1 | 観察Insightの配信改善 | 今日の様子だけの新しい掲載可能な発見を、意味重複を抑え翌朝の既存日次レポートで届ける。既存記録/レポートを変更しない。 |
| 2 | 複数指標の記述的Insight | 実測日・評価日・品質を合わせて再利用し、相関を因果として説明しない。記録不足では省略する。 |
| 3 | 活動量予測モデルのオフライン比較 | 回し車の距離/回転数を初対象に、中央値/EWMAと候補モデルを時間順に比較する。Prediction Readyと不確実性を検証する。 |
| 4 | ユーザー横断の階層モデル | 適切な同意と保護を前提に、種類/環境/個体差を分離し、未知個体への評価と説明可能性を確認する。 |
| 5 | 疾患関連リスク予測の研究 | 獣医師確認ラベル、十分な対象数、外部検証を満たす研究として実施する。未検証の診断機能として提供しない。 |

今回の開発対象は段階1と本ロードマップの保存だけである。段階2〜5のスキーマ、モデル、研究データ集約を今回の作業へ追加しない。
