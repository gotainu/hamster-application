# 今日の星・累計報酬の設計

更新: 2026-09-17

## 現在実装している範囲

- Homeの「総合コンディション」の下に「今日の記録」を表示し、横幅を使った大きな星3枠だけを置く。条件の説明は星をタップした画面に置く。
- 1枠目は、その日にアプリを開いたときに埋まる起動ボーナス。2枠目は昨日の走行記録、3枠目は今日の様子。
- 走行・様子の星は既存の記録の有無から計算する。同じ日の再編集では増えない。体重は毎日の星に含めない。
- 星の獲得台帳、累計、50個達成状態、ドロワーの「星の累計」と祝福画面をローカル実装している。プログラムの開始日は2026-09-17（日本時間）で、過去の記録には遡及付与しない。
- 累計機能は公開環境へ反映済みで、`STAR_REWARDS_BACKEND_ENABLED`は既定で有効。障害時だけビルド時に`false`を指定して停止できる。3つの今日の星はこの設定と独立して表示する。
- 今日の3枠はまだ既存の記録を直接読んでいる。サーバー台帳が反映された後、日ごとの表示と累計の一致をE2Eで確認する。

## 累計を導入するときのルール

1. 星はユーザーアカウント単位とし、`日付 × ミッション`を一意キーにする。1日につき各ミッション最大1個、合計最大3個。走行のミッション日付は走行記録の翌日、様子のミッション日付は記録当日とする。
2. 起動ボーナスは認証済みユーザーがアプリを開いた日をサーバーで記録する。クライアントの表示だけを累計の根拠にしない。
3. 走行・様子は既存の`distance_records`と`daily_checkins`の対象日ドキュメントを根拠にする。編集・保存の回数では加算しない。起動時にも当日の対象ドキュメントを照合して、前日に保存された走行記録を取りこぼさない。
4. 初回導入の開始日は2026-09-17（日本時間）とする。既存の記録を遡って星に変えず、起動履歴も推測して付与しない。
5. 日付は初回の日本限定提供では日本時間で判定する。将来の海外提供時にはアカウントのタイムゾーンを検討する。
6. 獲得済みの星は、後で記録を編集・削除しても取り消さない。獲得台帳はサーバー側で一意キーにより作成し、累計を台帳から再計算できるようにする。健康レポートに使う実データは、星の獲得履歴ではなく現存する記録から読む。

## 将来の継続ルールに備える設計

- 累計ドキュメントは、現在保有する`balance`（表示互換の`total`も同値）と、失効しない`lifetimeEarned`を分けて保存する。50個の解放条件は後者で判定する。
- 将来「3日連続で星を得られなかったら保有星を失う」を導入する場合は、`balance`だけをゼロにし、`lifetimeEarned`、獲得台帳、解放済みコンテンツは残す。
- 失効は初期提供では無効とする。導入時には、失効までの残り日数、例外、復帰方法を事前に明示し、利用者が選べる通知設定とともに提供する。
- 2日連続の獲得ゼロ通知は、日次のサーバージョブで`lastAwardDateKey`を基に判定する。通知v2の頻度制御・夜間停止・休止設定を必ず適用し、同じ失効予告を繰り返し送らない。

## 50個達成イベントと特別コンテンツ

- 累計が初めて50個に達したとき、達成イベントを一度だけ記録してアプリ内で祝う。同じ編集や再ログインでは再発火しない。祝福画面を閉じた後に`seenAt`をサーバーで記録し、閉じる前にアプリが落ちた場合は次回に再表示できる。
- 達成時に解放される内容は後で決める。候補は星に囲まれたハムスターのイラスト、これまでの飼育環境を振り返るレポート。
- 内容を一回限りで消すと見逃しやすいので、達成後は再閲覧できる解放型コンテンツを推奨する。未達成者には見せない。
- ドロワーの「星の累計」はサーバーが作成した累計ドキュメントがある時だけ表示する。数値を推測する仮表示はしない。

## 受け入れ条件

- 同じ日・同じミッションを繰り返し保存しても星は1個だけ。
- アプリを開くと当日の起動星が1個埋まり、翌日の表示はその日の記録に切り替わる。
- 累計が49から50へ進むと達成イベントは1回だけ発生し、再起動後も解放状態が残る。
- 本番反映後のE2Eで、Homeの3枠、詳細画面、累計、ドロワーの数値が一致することを確認する。累計有効版はエミュレーターへ導入済みで、ログイン後の確認が残る。
