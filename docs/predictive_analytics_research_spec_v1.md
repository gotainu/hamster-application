## 0. 文書の使用方法と変更管理

### 0.1 この仕様が守るもの

- 研究対象は**活動量の数値予測（T-A）**と**次の全体観察回答の予測（T-O）**を分ける。既存ロードマップはT-A先行、添付原案はT-Oを初期主目的としており、優先関係は未確定（C-01／P-12）。病気の診断や発症確率の提供を、現時点の成果として主張しない。
- 導入順序は **仕様固定 → 観察・時刻・同意のデータ品質整備 → オフラインモデル比較 → 前向きシャドー検証 → 安全性評価 → 将来のランダム化表示試験**。

- 個体単位・世帯単位のデータを将来統合する場合、同意、アクセス制御、削除・用途制限と検証独立性が前提。

## 1. 観察回答トラック（T-O）の研究課題とエンドポイント

### 1.1 T-Oの主要研究質問（研究全体の着手優先順位はP-12）

**既知の時点までに取得できた体重・活動量・環境・過去の観察・属性から、次の観察機会に飼い主がどの全体回答を行うかを、単純な基準より正確に予測できるか。**

- 主目的変数（順序カテゴリ）：`normal=0`, `slightlyConcerned=1`, `veryConcerned=2`。
- これは**飼い主による観察記録の分類**であり、獣医師による疾病診断ではない。
- 二次評価では全体回答の `concern_recorded = (Y >= 1)` を候補とする。原案の`changed_or_concerned`は同じ写像の仮名であり、項目別`changed`／`concerning`とは別の変数。ラベル名称・契約はP-02で確定し、二値化だけに最適化して3段階の意味を捨てない。
- 稀な `veryConcerned` の検出能力は十分な事象数が得られるまで別評価し、性能が不明な場合は「未評価」と記録する。

### 1.2 研究初版で採用する予測時刻・ラベル【P-01／P-02部分決定】

- `T0 = D 09:00 JST`、`T1 = D+1 09:00 JST`。対象窓は`(T0,T1]`（T0ちょうどを除き、T1ちょうどを含む）。特徴量の知識締切はT0から延ばさない。
- 観察時期とoriginal受理時刻の両方が窓内と確認できる、新しい明示観察を候補とする。提出時刻だけで、予測後に観察したとは認定しない。候補選択と証拠は[dataset契約](prediction_dataset_contract_v1.md)に従う。
- 主ラベルは選択した観察の**初回回答値**。同じ観察について、`L = T1 + 24時間`までの訂正を反映した値を**比較・感度分析用**に保持し、独立した2観察へ水増ししない。
- Lまでに選択した観察が取り消された場合は**ラベル欠測**とし、後続の観察へ自動差し替えしない。適格な回答がない場合も`normal`で補完しない。
- Lは研究初版の運用値。実データ評価で変更する場合はpolicy versionを上げ、旧dataset／予測snapshotを上書きしない。L後の訂正をこのversionへ混入させず、Lを延ばしても特徴量締切T0は変えない。
- 日別文書の最新状態だけで、初回回答・訂正・取消を再現できるとは限らない。観察ID・原受理時刻・revisionを用い、復元不能な期間は不明を保持する。
- 同率受理の研究採用規則、時刻不明・日付精度の観察の最終的な採否、タイムゾーン移動等は未承認の残件。既存の架空fixture検証規則を、そのまま実研究で承認済みと扱わない。

**旧案の位置付け**：「提出時刻だけで窓内判定」「最後／最も強い回答への置換」「取消後に次候補へ差替」「L未決定」は以前の案・比較の経緯であり、上記採用規則と競合する現行ルールではない。

**留意**：予測対象は観察回答であり、24時間連続の健康状態や疾病の有無ではない。これは研究設定の決定で、既存09:00 JST Schedulerの変更や実験開始を伴わない。

### 1.3 セカンダリ研究課題

1. **変化の立ち上がり**：それ以前に`normal`が明示的に記録されていた状態から`slightlyConcerned/veryConcerned`へ移る初回の予測。
2. **既存の気になる様子の継続**：昨日既に懸念がある場合の将来回答を予測（早期検知とは別に評価）。
3. **活動量数値予測（T-A）**：既存ロードマップでは初期予測対象。T-Oの二次評価へ格下げせず、日次走行距離・回転数を独立して検証する。将来、検証済みの予測残差をT-Oへ渡す場合もout-of-fold／時点整合性を別途確認する。
4. **獣医療イベント**：獣医師による診断・受診結果を別エンドポイントとして将来検証。イベント希少性、診断日≠発症日、受診選択バイアスを扱う。

### 1.4 主張してはならないこと

- 飼い主の`veryConcerned`を「病気だった」と同一視する。
- `normal`や回答欠測を「病気がない」とみなす。
- 高い予測確率だけで「明日病気になる可能性が高い」と表示する。
- 回し車の利用が少ない＝福祉状態が悪い／多い＝健康と決める。
- 観測された関連を因果関係、診断、発情周期の独立証明として説明する。

## 3. Point-in-time correctness：データ漏洩防止の契約

### 3.1 時間の3種類

- `observedAt`：ハムスターの状態・活動が対象とする実際の時刻／期間。
- `serverReceivedAt`：サーバーへ届いた時刻。未来の予測に使えたかの判定に使用。
- `effectiveAt`：設定・環境・機器の変更が有効になった時刻（別途記録）。

DistanceRecordsRepoは再保存でもcreatedAtを更新する。DailyCheckinのpayloadは新規判定時だけcreatedAtを設定し、updatedAtは最終更新を示す。どちらも訂正前の回答／入力履歴は保持しないため、**createdAt／updatedAtだけを不変の受信・提出履歴とは扱わない**。Firestore updateTimeも現在versionの更新時刻であり、過去versionの内容を再現する履歴ではない。

### 3.2 学習データの不変条件

- 時点`t`の入力特徴量は、**観測時刻と取得可能時刻がともに予測締切以前**であることを確認。
- 当日の観察回答や、その回答を含んで算出された健康スコアを、その回答の予測へ入力しない。
- 過去日への後入力、削除、訂正、センサーの遅延転送は当時の特徴量集合へ逆流させない。
- 予測対象期間と特徴量の集計窓を個別に保存。Silverの同一`dateKey`は同時点・同期間の証拠ではない。
- データ品質欠損時は「不可／不足」を許し、実測0や`normal`への補完を行わない。
- 再学習・特徴量正規化・周期推定・ハイパーパラメータ選択は**学習区間のみ**で実施。

### 3.3 時点別version・後入力・日付境界の研究契約

- 将来の研究入力は論理観測ID、観測対象期間、初回受信イベント、訂正versionとその受信時刻を関連付け、cutoff時点で存在したversionを選ぶ。再送は同じイベントとして重複排除し、訂正は後続versionとして扱う。具体的保存先・監査履歴は未実装（G1）。
- 過去日Sの記録がcutoff後に到着した場合、そのcutoffでの特徴量へは不採用。後続の予測で利用する際は観測日の古さと受信遅延を保存する。Lまでの観察取消は§1.2のとおりラベル欠測とする。正規削除後の研究利用・保持・削除範囲はP-09で別途決定する。
- 固定パスmain_petだけを永続的な研究個体IDとみなさず、同意範囲内の仮名化個体／世帯キーと、その個体情報が有効だった期間の対応を将来の契約で確認する。プロフィール更新を別個体の過去記録へ遡及適用しない。
- 種類・生年月日・性別・飼育環境も、予測時点に確認できたversionを使用する。後日の誕生日訂正・性別確認を過去入力へ自動反映しない。実際の有効日と、当時その情報を知り得た時刻を区別する。
- 集計区間の終了、元データ取得可能時刻、特徴量・周期推定のasOfを検証する。最新の再計算Silver／Goldがあるだけでは、過去cutoffの学習データを合格にしない。
- 日付だけの記録から測定時刻を捏造しない。日次活動量は集計区間の終端と計測coverage、点測定の体重は実測日の精度を保持し、cutoff前に完了した観測か判別できない値は除外／保留する。
- UTCの時刻とJSTのdateKey、観測日、受信日、予測日を別に保存する。現在の日次UIは端末local dayのdayKeyを使うため、タイムゾーン不明の旧記録をUTC/JST変換だけで別日に修復しない。研究の対象タイムゾーン・移動時の扱いはP-01／P-15。
- 欠測・invalid・後入力・実測0・未回答を別の品質状態として保持する。統計的補完を将来比較する場合も学習区間だけで学習し、実測ラベルや実観測を生成したことにしない。初版の周期実測系列は0埋め／持ち越しをしない。

### 3.4 観察回答の選択的欠測

気になる日にだけ回答する利用者と毎日回答する利用者では、記録の偏りが違う。`P(Y | X, 回答が提出された)`は、全日についての状態確率とは異なる。予測品質とともに、回答率、回答欠測のタイミング、回答者ごとの差を別に評価する。

## 4. 周期長・位相・振幅の推定モジュール

### 4.1 推定対象を厳密に区別

1. **Activity periodicity**：回し車活動データから見いだされる周期成分。
2. **Cycle length** `periodDays`: 活動周期の候補日数。
3. **Phase** `phaseRadians`／`referenceEpoch`: 推定周期のどこにいるか。基準epochなしの位相数値だけは保存しない。
4. **Amplitude**／`signalToNoise`: 周期成分の強さと不確実性。
5. **Estrous-cycle corroboration**：独立した観察から発情周期との対応を検証できたか。活動データだけなら`unverified`。

### 4.2 周期解析の最小実験【H-01】

- 入力：**実観測の**時系列 `[(timestamp, activity, coverage, wheelConfigVersion)]`。欠測0埋めや前方補完なし。
- 対象：初期探索帯は提供原案の候補である**4〜10日前後**を保持する（過去の直接合意は確認していない）。境界効果と約4日付近を検討するため、研究上は**例：3.5〜10日**も比較する（**探索範囲・刻みは未確定**）。整数周期限定としない。
- 規則的な十分な日次系列：ACF（自己相関）・周期回帰を候補に。
- 不規則な観測：generalized Lomb–Scargle（floating mean、観測coverageや測定誤差に応じた重みを検討）。
- 単一のピークより、候補周期の複数性、4日・8日等の高調波、曜日周期、サンプリング由来のエイリアスを評価。
- 周期有モデルを、周期なし＋年齢／長期トレンドモデルと比較する。季節性・環境変更・活動量分散の変化を無視しない。

候補周期`T`に対する周期回帰の概念形：

\[
 r_t = a\cos\left(\frac{2\pi(t-t_0)}{T}\right)
     + b\sin\left(\frac{2\pi(t-t_0)}{T}\right) + \epsilon_t.
\]

各`T`で`a,b`を推定し、振幅`√(a²+b²)`、位相と基準epochを導出。**ACF単独から絶対位相は得られない**。同じ日付の整数丸めが位相の時間精度を制限する。

### 4.3 偽陽性を抑える検証

- 多数の周期候補を探索することによる多重比較を扱う。
- 独立Gaussian noiseを仮定したperiodogramのFAPを、自己相関のあるデータへ無条件に流用しない。
- 自己相関構造と欠測パターンを考慮したシミュレーション／適切なブートストラップ等でノイズ帰無モデルと比較。
- 学習区間を変えたときの周期長・位相・振幅の安定性を調べる。
- 将来期間の走行距離または観察回答の予測が、**周期なしモデルより実際に改善するか**を必須の採用条件にする。
- 有意そうに見えても、予測性能が悪い・位相が不安定・観測coverageが低いなら`periodicity_status=insufficient_or_unstable`。
- 推定に失敗した個体へ4日周期を補完しない。

### 4.4 生理周期についての制約

約4日の発情周期に関する参照はメスのシリアンを対象とするJanik & Janik (2003)（§16）。同論文は活動・概日位相と独立した発情観察を扱う研究であり、家庭の日次走行距離だけから発情位相を同定できることを実証した資料ではない。独立確認の取得方法・実施者・同意・動物福祉上の可否はP-03として専門家と定め、飼い主へ侵襲的確認を求める仕様にはしない。


- メスのシリアンハムスターには約4日の発情周期に関する研究知見がある。ただし、**活動周期と発情周期は同義ではない**。
- 適格条件は種類・性別・年齢／成熟・繁殖／避妊状態、関連する独立観察の有無などを検討。情報が欠ける個体には「発情周期を確認」と表示しない。
- 「推定活動周期」は雄・他種でも統計上の探索対象になりうるが、**性周期の説明へつなげない**。
- 多数のユーザーから推定された周期分布を、将来、種類・属性別の事前分布へ利用する場合は、**推定できた個体だけの偏った標本**であることを考慮する。
- 集団の分布を使っても、個体の位相は個体ごとの観測から推定する。集団で位相を共有しない。

## 5. 観察回答の確率モデル

### 5.1 比較するモデル

| 段階 | 方法 | 目的 |
|---|---|---|
| M0 | 全体の過去クラス頻度、直近明示回答、個体ベースライン等の単純予測 | 必須比較対象 |
| M1 | 正則化付き順序ロジット | 第一候補、順序3分類 |
| M2 | 部分比例オッズ／正則化付き多項ロジット | 比例オッズ仮定の影響を確認 |
| M3 | 年齢の非線形項・少数の交互作用 | ライフステージ変化を扱う |
| M4 | 推定活動周期項付きM1/M3 | 周期が未来予測に寄与するか |
| M5 | 階層順序モデル・混合効果モデル | 利用者・個体増加後の個体差推定 |

数値予測のRidge/GPR/負の二項モデルはT-Aの**別実験**とし、T-O分類器と評価結果を混同しない。LLMによる自由記述解釈は今回および初版研究の対象外であり、別途承認のない生成AI/API利用や疾病リスク表示を追加しない。

### 5.2 順序ロジットの契約

`Y∈{0,1,2}`、`k∈{0,1}`について、

\[
P(Y \le k \mid X)=\sigma(\theta_k-\eta(X)),\quad \theta_0<\theta_1.
\]

- 出力は`p_normal`, `p_slightly_concerned`, `p_very_concerned`。合計1、各値は[0,1]。
- 基本形の比例オッズ仮定が崩れる場合は候補モデルを比較し、**後付けの当てはまりだけで複雑化しない**。
- 希少な`veryConcerned`の完全分離・係数発散への対策として正則化、事前分布等を検討。
- モデルに明示回答が不足する利用者では個人別モデルを無理に学習しない。

### 5.3 年齢と環境の変化

- 最初から「幼年・青年・老年」ごとに完全分割せず、年齢を連続値として扱い、必要なら低自由度スプラインにする。
- 年齢と活動量の交互作用は仮説候補にするが、最初からすべての係数を時変にしない。
- 環境設定変更は`effectiveAt`以降の特徴量へ反映。過去全日に現在のケージ情報を適用しない。
- 短期の適応基準と中長期の変化モニターを分ける。モデルが変化に順応したからといって長期変化の証拠を消さない。
- 将来の階層モデルでは、個体効果・飼い主／世帯の回答傾向を可能な限り分離する。1飼い主1匹の構造では両者を完全に識別しにくいと明記する。

### 5.5 活動量トラック（T-A）の位置付け

既存ロードマップ§3／§5／§10の距離・回転数予測を維持する。基準は既存の個体中央値／EWMA、距離の候補はRidge／ベイズ回帰／GPR、回転数はPoisson／負の二項回帰。種類・年齢・環境・計測方式・観測時間・実測0と欠測を区別し、過分散や測定条件への適合性を確認する。

T-AのMAE／RMSE等の数値誤差、予測区間coverage／幅、個体・世帯外の汎化と、T-Oの順序確率／校正を混ぜない。モデル選択・前処理・周期推定は学習区間に限定する。主数値指標・target window・学習／検証期間は活動量実験計画として別途確定が必要で、本書は実験書や学習実施を新設したものではない。

周期項はT-A／T-Oそれぞれで周期なし基準に対する未来予測改善を評価する。一方で採用された周期を、もう一方へ無検証で適用しない。T-A由来の予測残差をT-O特徴へ渡す場合、各foldで学習したT-Aによる予測を使い、T-O検証ラベルを含む期間でT-Aを学習しない。

## 6. 学習・検証・Prediction Ready

### 6.1 評価の段階

1. **後ろ向き探索**：既存記録から品質・クラス比率・欠測構造を把握（ただし提出履歴がない過去日は将来予測の完全な再現不可）。
2. **時間順のオフライン検証**：学習期間→未来期間を順次進める rolling-origin / forward chaining。
3. **個体／世帯外汎化**：一度も学習に使っていない世帯・個体への適用を別に評価。
4. **前向きシャドー検証**：予測を実際の時点で固定し、その後の観察回答を待って評価。最も重要な運用評価。
5. **ランダム化表示試験**：予測表示が行動・記録・負担へ及ぼす影響を別途評価。

### 6.2 T-Oの評価指標（T-Aは§5.5、別の評価契約）

- 主：**Ordinal Ranked Probability Score (RPS)** など順序確率に適したproper scoring rule。対照モデルとの差分と不確実性を報告。
- 副：多クラスlog loss、クラス別Brier score、校正図、予測確率帯ごとの実測割合。
- 関心事象：`Y≥1`のPR-AUC、感度、陽性的中率、偽陽性数／個体・月、予測のリードタイム。`veryConcerned`は事象数と信頼区間を必ず併記。
- 品質：予測可能な個体・日の割合、回答率、欠測率、観測coverage、モデルが`abstain`した割合。
- 公平性：種類・年齢帯・性別／状態・飼育環境・記録方式・飼い主／世帯特性で、十分な標本がある場合に性能差を確認。
- 誤った安心感・通知疲れ：表示段階で評価。予測の「低リスク」で既存警告を抑制しない。

### 6.3 自己相関と稀な事象

- 同じ個体の連続した懸念日を独立イベント多数として水増ししない。エピソード単位で評価する。
- 検証時の不確実性推定は個体／世帯や時系列の依存構造を考慮。ランダム行分割を禁止。
- クラスが希少なら高いaccuracyでも有用とは限らない。陽性的中率と誤通知負担を重視。
- 同じ多数のモデル／周期を試して良かったものを、独立した確認期間なしに本番採用しない。

### 6.4 Prediction Ready【G：未数値化】

固定の閾値（例：30日でready）を今は定めない。次の**すべて**を満たすことを候補とし、数値を事前登録／学習曲線・シミュレーションで決める。

- T-Oはラベルの有効回答・クラス別事象エピソード・個体／世帯数、T-Aは対応付けられた実測・観測期間・測定方式ごとの標本が十分。どちらも単なるdocument数で判断しない。
- 重要特徴量の時間整合性とcoverageが確保される。
- 各トラックの基準モデル（T-Aの中央値／EWMA、T-OのM0）より、事前に定めた指標で意味のある改善がある。
- T-Oは確率の校正と`Y≥1`検出負担、T-Aは数値誤差と予測区間のcoverage／幅が、事前に定めた基準を満たす。
- 検証対象集団と実際の利用者が比較可能。
- モデル不確実性と欠測に応じた**予測保留（abstain）**が機能する。

`baseline_ready`、`periodicity_ready`、`prediction_ready`、`display_ready`を別stateで管理する。

## 7. シャドーモード（将来の前向き検証・未実施）

### 7.1 原則

- 将来承認された研究対象について、新モデルの予測値・警告はユーザーへ**表示しない**。シャドーでもデータ収集／学習／保存には用途に応じた同意と権限が必要であり、全ユーザーを自動的に対象にしない。既存の健康評価・通知・受診案内は維持。
- 予測は指定された基準時刻に発行し、**生成された時点の入力・モデルversion、T-Aの予測値／区間またはT-Oの確率を不変保存**。
- 後から対象窓と対応する実測（T-A）または回答イベント（T-O）をjoinし、結果は別データに保存。予測後に到着した事実を予測時点の入力へ逆流させない。
- 予測が利用者やサポート担当者へ漏れて行動に影響しないよう、通知・ログ・運用ツールの露出範囲を区別。
- シャドーに入れたから自動的に健康イベントの検証ができるとは限らない。T-Aは活動量の実測、T-Oは全体観察回答が主要ラベルであり、疾病ラベルと区別する。

### 7.2 観測すべき運用指標

処理失敗、時刻のずれ、遅延入力、ラベル欠測、予測保留、モデル別性能、データ品質、誤通知に相当する潜在的イベント（**実表示はないため仮想アラートとして評価**）、モデルのドリフト。

### 7.3 段階終了条件

前向きの性能・校正・データ品質が事前登録基準を満たし、獣医師等によるリスクレビューを経た場合に限り、ユーザー向け表示試験の設計を審議する。**本書では表示機能を許可しない**。

## 8. 将来のランダム化表示試験（RCTに近い設計）

### 8.1 主要仮説

**新しい予測情報を表示することで、飼い主の観察・記録・対応が変わるか。さらに実際の役立ち方が通知負担や不安を上回るか。**

「表示群で`心配`が増えた」だけでは、早期発見と回答への誘導を区別できない。

### 8.2 基本デザイン【H／P】

| 項目 | シャドー群 | 表示群 |
|---|---|---|
| 同じ凍結モデルの推論 | 実施 | 実施 |
| 新予測の表示 | 非表示 | 適格な場合のみ表示 |
| 既存健康警告・標準機能 | 同一 | 同一 |
| 観察記録の依頼・UI | 原則同一 | 原則同一（新予測部だけ追加） |
| データ品質・受診結果 | 同条件で収集 | 同条件で収集 |

- **ランダム化単位は原則、世帯／飼い主単位で固定**（複数匹、複数端末への介入漏れを防ぐ）。
- 研究開始前に同意、適格条件、割付割合、層別要因、試験期間、主要・副次評価指標、サンプルサイズ／検出力を決定する。**例示の50:50をそのまま確定値にしない**。
- 割付結果にかかわらず予測を計算し、表示の有無を別フィールドとして保存する。
- 主要解析はランダムに割り当てた群で比較（intention-to-treatに相当する原則）。「実際に画面を開いた人」だけで主解析しない。
- モデル・閾値・文面・更新規則は期間内で原則固定。変更は新protocol／modelVersionで扱う。
- 危険な症状やユーザーの異常入力に対する既存の案内は、両群で同等に保持する。

### 8.3 評価すべきものを分ける

| 軸 | 指標候補 | 注意点 |
|---|---|---|
| 予測性能 | T-Aの数値誤差／区間coverage、T-OのRPS／確率校正／事象検出 | 各トラックをシャドー段階で検証 |
| 記録への影響 | 入力頻度、カテゴリ変化、欠測 | 表示が回答そのものに影響する |
| 行動への影響 | 受診相談、観察行動、追加測定 | 有益／過剰反応の双方を測定 |
| 福祉・安全 | 早期の適切な対応、誤通知、不安、通知疲れ | 外部確認可能な結果も別評価 |

- 観察回答や診療イベントは記録の偏りを受けるため、別の資料で確認できる結果も検討する。ただし検証資料なしの受診記録を独立した真値とみなさない。
- 観察頻度を群間で揃えたとしても、無回答・途中離脱が発生した場合は欠測理由と群差を評価する。
- 表示による誘導が観察回答へ影響する問題は、RCTで総効果を評価しつつ、原因の内訳が識別できるかは別途研究課題とする。
- 将来、通知機会ごとのマイクロランダム化を検討する場合は、翌日までの持続効果と安全性を別に審査する。

### 8.4 イベント／割付データ契約【論理例】

- `experimentAssignment`: `experimentId`, `householdKey`, `arm`, `randomizationUnit`, `assignmentProbability`, `assignedAt`, `consentVersion`, `protocolVersion`。
- `predictionExposure`: `predictionId`, `arm`, `eligibleAt`, `dispatchedAt`, `renderedAt`, `openedAt`, `suppressionReason`, `copyVersion`, `deviceMetadataMinimized`。
- `outcomeEvent`: `observedWindow`, `submittedAt`, `condition`, `responseSource`, `missingnessStatus`, `vetOutcomeLink`（必要時）。
- 実験データはアクセス制御・保存期間・同意撤回を前提とし、Firebase Analyticsへ診療情報や自由記述を送信しない。

### 8.5 停止条件の例【未数値化】

不正な低リスク表示、過度な通知、著しい校正悪化、データ漏洩、群間での重大な悪影響、モデルの予測対象と表示文言の不一致。停止閾値・責任者・対応手順は試験開始前に確定する。

## 11. プライバシー・同意・安全性・研究運用

- ユーザー横断の研究利用は、アプリ運用に必要な処理と目的・同意を分ける。既存データの利用可否を自動的に仮定しない。
- 研究用には個体・世帯の仮名化IDを使う。学習用データへのアクセス、監査、目的外利用禁止を設定。
- 生データ、自由記述、診療資料の取り扱いは必要最小限。予測結果をアナリティクスへ内容ごと送信しない。
- 同意撤回・データ削除時に、Firestore、派生Gold、研究コピー、エクスポート、学習／検証データ、予測snapshot、学習成果物、バックアップへの影響評価と実行手順を設ける。すべての学習済み重みから個別データを即座に除去できるとは約束しない。
- **不変性は通常の再計算・モデル更新による上書き禁止であり、本人の正式な削除・承認された保持期限処理を阻止する契約ではない。** 現行[`deleteMyAccountAndData`](../functions/src/index.ts)は本人確認を伴いusers/{uid}配下を再帰削除する。研究用コピー・成果物・別環境までこの経路だけで削除できるとは保証しない。今回、この処理や保存済みreportを変更しない。
- 同意撤回（将来収集／利用停止）とデータ削除（保存済みデータへの対応）を区別し、対象・受付時刻・進捗・完了証拠・例外／法的保持の判断主体を定める。未対応データを新しい研究へ再投入しない。モデルの再学習・使用停止・再配布、個別除去が困難な成果物への対応方針はP-09／P-14で事前に明示する。
- 削除対応で通常履歴を書き換えるのではなく、必要な削除・利用停止を専用の権限制御と監査で実施する案とする。監査へ生データを複製せず、backup復元時にも削除／撤回を再適用できる設計を将来検証する。具体的保持期間と法的判断は未確定であり、文書登録を研究倫理審査・同意取得の完了として扱わない。
- 保存期間とバックアップ上の扱い、最小保有期間、集団統計の公開可否、サンプル数による匿名化条件を実装前に決定。
- 研究として実施する際には所属機関・獣医療専門家・適用法令や倫理審査の要否を確認。
- **未検証の「健康」「疾病」「発情」推定を医学的・獣医学的診断のように表示しない。**

## 12. テスト・シミュレーション・検証マトリクス

### 12.1 データ契約

- [ ] `normal`の明示回答と、保存時に自動補完された`observationLevels.normal`を区別できる。
- [ ] 未回答日／未来日／過去日訂正／同日の複数提出で、対象ラベルが誤って生成されない。
- [ ] `observedAt`・`serverReceivedAt`・`effectiveAt`の時刻とJST日付境界が整合。
- [ ] 実測0／欠測／持ち越し／センサー停止／手入力が区別される。
- [ ] 後入力した過去データを当時の予測特徴量に混入しない。
- [ ] Observation Catalogのversion変更・旧IDで予測ラベルの意味がずれない。
- [ ] 年齢、性別unknown、飼育環境の変更履歴なしでも安全に`abstain`する。

### 12.2 周期解析

- [ ] 周期なしノイズで、周期の虚偽検出率が許容範囲内。
- [ ] 既知の4.2日周期を持つ合成データで候補探索と位相復元が妥当。
- [ ] 欠測・不等間隔・手入力・センサーcoverage変化でも誤検出を抑制。
- [ ] 4日／8日の高調波・7日習慣・年齢トレンド・環境変更で偽陽性をチェック。
- [ ] 推定周期の位相を未来情報から逆算していない。
- [ ] 活動周期のみを根拠に発情周期としてラベル付けしない。
- [ ] 周期候補を採用しても予測改善がなければ使わない。

### 12.3 分類器・品質

- [ ] 各確率は[0,1]で、合計がほぼ1。
- [ ] 順序3分類が不均衡な場合、収束失敗・完全分離時に予測を保留。
- [ ] 時間順検証と新規世帯検証の両方で性能を報告。
- [ ] 前処理・周期推定・モデル選択が学習区間外の未来情報を使わない。
- [ ] 基準モデルとのproper scoring rule比較、校正、信頼区間を保存。
- [ ] 悪い結果や十分な事象数不足でも、`ready`を誤ってtrueにしない。
- [ ] 同一状態が長期継続するエピソードで独立事象の水増しを行わない。

### 12.4 Shadow・RCT・セキュリティ

- [ ] シャドー予測がユーザーUI・通知に露出しない。
- [ ] 予測snapshotと後から入った観察回答を別記録として扱う。
- [ ] 新旧modelVersionの予測が既存レポートや健康警告を書き換えない。
- [ ] 世帯単位の割付が複数端末・複数個体で矛盾しない。
